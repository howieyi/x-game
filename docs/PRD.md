# PRD — 记忆翻牌 (Memory Match) 游戏化平台

> 产品需求文档。本文件由 `work-prd` 维护。后续变更请走 `work-prd-change` 流程。

---

## 1. 背景与目标

### 1.1 背景
仓库已基于 `better-t-stack` 完成脚手架（React + TanStack Router + Hono + tRPC + Better-Auth + Drizzle + PostgreSQL），并存在一份独立 HTML 小游戏 `docs/memory-match.html`（记忆翻牌，4×4 牌阵，7 种主题，WebAudio 合成音效）。当前游戏纯前端单机，仅使用 `localStorage` 记录个人最佳，**无登录、无云端记录、无排行榜**。

### 1.2 目标
在现有工程基础上叠加三个能力，把单机 HTML 小游戏升级为**多用户可登录、可记录、可上榜**的轻量游戏化平台：

| 能力 | 落地形态 |
| --- | --- |
| G1 登录 / 注册 | 基于已有 Better-Auth；登录后才可上榜；未登录仍可匿名试玩 |
| G2 游戏数据记录 | 每次对局入库；提供"我的战绩"页 |
| G3 排行榜 | 按主题分别排行，取 Top N，登录用户提交后自动刷新 |

### 1.3 非目标
- 不做社交分享、好友系统、评论、积分商城。
- 不做服务端游戏逻辑校验（信任客户端上报，依赖登录态与基础合法性）。
- 不替换现有 Better-Auth 实现。
- 不重写 `docs/memory-match.html`（保留作为行为基线参考）。

## 2. 用户角色与场景

### 2.1 角色
- **访客 (Guest)**：未登录。可玩任意主题，**不入库、不上榜**，仅本地最佳（沿用现有 localStorage 行为）。
- **玩家 (Player)**：已登录。可游玩、入库、上榜、查看自己的战绩与全局排行榜。

### 2.2 核心场景
1. **新用户进入**：访问 `/` → 看到欢迎页 + CTA「开始挑战」（登录后才可上榜的提示）→ 点击进入登录/注册页。
2. **登录后游玩**：玩家在 `/game` 选择主题 → 开始游戏 → 完成对局 → 自动入库 + 自动刷新右上角"我的最佳" → 看到"是否上排行榜"的提示。
3. **查看战绩**：玩家在 `/stats` 看到按主题分组的卡片：总场次 / 最佳步数 / 最佳时长 / 3 星次数；下方为该主题历史记录列表。
4. **查看排行榜**：访客或玩家在 `/leaderboard` 切换主题 tab 查看 Top 10；登录玩家提交成绩后立即看到自己是否入榜。

### 2.3 边界场景
- **离线 / 提交失败**：网络抖动时入队重试 3 次，仍失败则提示"成绩未保存"，但允许继续游玩。
- **重复提交同一局**：以前端标记为准（每局唯一 `clientNonce`，服务端唯一索引去重）。
- **登出后访问受保护页**：跳转 `/login`，登录成功后回到原页面。

## 3. 功能需求

### F1 登录 / 注册体系（G1）
- **F1.1** 复用 `apps/web/src/components/sign-in-form.tsx` 与 `sign-up-form.tsx`。
- **F1.2** 复用 `apps/web/src/routes/login.tsx`（默认显示注册，切换显示登录）。
- **F1.3** 复用 `apps/web/src/components/user-menu.tsx`（头像菜单 + 登出）。
- **F1.4** Header 在登录态增加「游戏 / 战绩 / 排行榜」三个导航入口。
- **F1.5** 不引入第三方登录（GitHub/Google 等），仅保留邮箱密码。

### F2 游戏数据记录（G2）
- **F2.1** 数据模型 `gameRecord`：每完成一局（8 对全匹配）持久化一条。
- **F2.2** 字段：`id`、`userId`、`theme`、`moves`、`seconds`、`stars`、`isNewBest`、`clientNonce`、`createdAt`。
- **F2.3** 入库触发：登录用户完成对局时，前端调用 `game.submit`（mutate）→ 服务端写库 → 返回 `{ record, isNewBest, bestRecord }`。
- **F2.4** 我的战绩页 `/stats`：每主题一张卡片，显示「总场次 / 最佳步数 / 最佳时长 / 3 星次数」+ 历史列表（分页 20/页，按时间倒序）。
- **F2.5** 匿名试玩不入库；UI 上需明确提示"登录后可保存成绩"。

### F3 排行榜（G3）
- **F3.1** 按主题分组（共 7 个主题），每个主题独立 Top 10。
- **F3.2** 排序规则：`moves` 升序，相同时按 `seconds` 升序，再次相同时按 `createdAt` 升序（先达成者在前）。
- **F3.3** 页面 `/leaderboard`：顶部主题 chip 切换，下方表格「排名 / 玩家 / 步数 / 时长 / 达成时间」。
- **F3.4** 仅登录用户的成绩入榜；提交后无需手动刷新，列表自动 invalidate。
- **F3.5** 当前用户不在 Top N 时，在列表底部展示一行"你的最佳：xx 步 / xx:xx（第 N 名）"。

### F4 游戏本体
- **F4.1** 将 `docs/memory-match.html` 的视觉与玩法移植到 React 组件 `apps/web/src/components/game/memory-match.tsx`。
- **F4.2** 保留：4×4 牌阵、7 种主题、WebAudio 合成音效、动效（翻牌 / 抖动 / 弹跳 / 粒子 / 模态）、响应式布局、`prefers-reduced-motion` 适配。
- **F4.3** 改造点：替换 `localStorage` 个人最佳为云端（登录态）；未登录态保留 localStorage 兜底。
- **F4.4** 改造点：新增「登录后保存成绩 / 上榜」流程，由 `game.submit` mutate 驱动。

## 4. 验收标准

| 编号 | 描述 | 通过条件 |
| --- | --- | --- |
| AC-1 | 注册→登录→玩一局→入库 | 数据库 `game_record` 表新增一条；前端 toast 提示"成绩已保存" |
| AC-2 | 提交成绩后排行榜自动刷新 | 同一 session 不刷新页面，排行榜列表出现自己 |
| AC-3 | 匿名试玩不入库 | 未登录态完成对局，`game_record` 表无新增 |
| AC-4 | 排行榜排序正确 | 同主题按 `moves` 升序、相同 `moves` 按 `seconds` 升序；构造 3 条不同数据人工核对 |
| AC-5 | 我的战绩展示 | `/stats` 按主题显示 4 项统计 + 历史列表 |
| AC-6 | 移动端可用 | iPhone SE 尺寸下游戏可玩，Header 不溢出 |
| AC-7 | 现有功能未被破坏 | `pnpm dev` 启动后 `healthCheck` 通过；登录/注册/登出链路无回归 |
| AC-8 | 主题切换重置对局 | 切换主题后 `moves`、`seconds` 归零 |
| AC-9 | 重复提交去重 | 同一 `clientNonce` 二次提交返回原记录，不新增 |
| AC-10 | 登出后访问 `/stats` 跳登录 | 路由守卫生效 |
